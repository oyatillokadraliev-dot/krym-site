# Сайт спортивного комплекса «Крым»

Статус: публичная часть (3 страницы) + админ-панель с базой данных для
филиала «Началовское шоссе» и общего контента (тренеры, расписание, отзывы).
Backend — Flask, шаблоны — Jinja2, БД — SQLite (см. раздел про БД ниже).

## Дизайн

Визуальный стиль переработан по образцу sportlifeclub.ru: строгая
чёрно-белая палитра, крупная типографика строчными буквами (не капслок),
прямоугольные кнопки без скруглений, пронумерованные блоки (01, 02, 03...)
с крупной декоративной цифрой у каждой секции. Фирменный янтарный цвет
сохранён только как точечный акцент — в кнопках, ссылках и цифрах цен,
а не как основной цвет страниц. Декоративные номера скрываются на
мобильных экранах (`.section-number`, `static/css/style.css`).

## Публичные страницы

- **Главная** (`templates/index.html`, маршрут `/`): hero, направления спорта,
  филиалы с адресами и ссылками на 2ГИС/Яндекс Карты, тренеры, тизер
  расписания (реальные вечерние занятия), отзывы из БД, CTA.
- **Цены** (`templates/prices.html`, маршрут `/prices`): переключатель между
  филиалами. Бабайка — 4 раздела (единоборства, бассейн, фитнес, клубные
  карты), цены заданы в шаблоне. Началовское шоссе — 2 раздела (бассейн,
  бокс), цены из БД — редактируются в админке.
- **Филиалы** (`templates/branches.html`, маршрут `/branches`): переключатель
  между Бабайкой и Началовским шоссе. У каждого — описание, направления,
  расписание по дням недели, прайс. Направления, тренеры и расписание —
  из БД; прайс Бабайки — в шаблоне, прайс Началовского шоссе — из БД.

## Админ-панель (`/admin`)

Простая авторизация: один логин и пароль (см. «Доступ» ниже). Разделы:

- **Тренеры** — карточки для обоих филиалов (CRUD).
- **Расписание** — занятия по дням недели для обоих филиалов (CRUD).
- **Цены** — только для Началовского шоссе (CRUD). Цены Бабайки через
  админку не редактируются — они зависят от 1С и пока заданы в коде сайта
  (см. «Почему цены Бабайки не в БД» ниже).
- **Отзывы** — модерация: скрыть/опубликовать, ответить, удалить.

Изменения в админке сразу отражаются на публичных страницах — они читают
данные из той же базы.

### Доступ

```
URL:    /admin/login
Логин:    admin
Пароль:   krym2026
```

**Обязательно смените пароль после первого входа** — либо через SQL
напрямую (`UPDATE admin_users SET password_hash = ... WHERE username =
'admin'`, хеш через `werkzeug.security.generate_password_hash`), либо
добавив форму смены пароля в админку (сейчас её нет — это естественное
развитие на следующем шаге).

## О базе данных: важное техническое примечание

БД реализована на **встроенном в Python `sqlite3`**, а не на PostgreSQL,
как было согласовано в исходном техническом задании. Это временное решение,
принятое по конкретной причине: среда, в которой ведётся разработка, не
имеет доступа в интернет и не может установить PostgreSQL или пакеты
Flask-SQLAlchemy / Flask-Login, которые для него нужны.

**Это не изменение архитектуры**, а способ показать вам рабочий результат
прямо сейчас. Код в `db.py` и `app.py` написан так, чтобы миграция была
минимальной:

1. Схема таблиц в `db.py` (`SCHEMA`) — это то же самое, что нужно описать
   как модели SQLAlchemy: один файл, прямой перенос полей.
2. Все запросы к БД идут через понятные функции (`fetch_trainers`,
   `fetch_directions` и т.д. в `app.py`) — их нужно будет переписать на
   ORM-запросы, но набор данных, который они возвращают, останется тем же,
   так что шаблоны (`.html` файлы) менять не придётся.
3. Авторизация админа сейчас на `flask.session` + `werkzeug.security` —
   рабочий и безопасный способ, но при реальном деплое стоит перейти на
   Flask-Login для более стандартной и расширяемой авторизации (несколько
   администраторов, роли и т.д., если понадобится).

**Перед деплоем на реальный сервер:**
```bash
pip install -r requirements.txt  # раскомментировать Flask-SQLAlchemy и т.д.
```
и переписать `db.py` на SQLAlchemy-модели с `SQLALCHEMY_DATABASE_URI`,
указывающим на PostgreSQL. Это отдельная, небольшая задача — готов сделать
её следующим шагом, когда будет доступ к реальному серверу с PostgreSQL для
проверки (здесь я не могу её протестировать вживую).

## Почему цены Бабайки не в БД

Решение было принято сознательно: филиал «Бабайка» подключён к 1С, и пока
не подтверждена возможность автоматически читать номенклатуру услуг из 1С
через API, цены там остаются в коде шаблона — чтобы не создавать второй,
независимый источник цен, который разойдётся с 1С. Когда придёт ответ от
поддержки 1С (вопросы в `pismo-podderzhke-1c.md`), это можно будет
пересмотреть: либо цены Бабайки тоже переедут в БД с ручным обновлением
через админку, либо будут подтягиваться из 1С автоматически.

## Запуск локально

Требуется Python 3.10+. Дополнительные пакеты не нужны — используется
только стандартная библиотека и Flask.

```bash
cd krym-site
pip install flask
python3 seed.py     # создаёт БД и заполняет её текущими данными (один раз)
python3 app.py
```

Сайт откроется на `http://127.0.0.1:5000/`, админка — на
`http://127.0.0.1:5000/admin/login`.

Файл БД создаётся в `instance/krym.db` — при повторном запуске `seed.py`
данные пересоздаются (кроме учётной записи администратора, если она уже
существует, чтобы не терять пароль).

## Технические примечания

- Шрифты (Google Fonts) и anime.js подключены через внешние CDN — я
  тестировал вёрстку в среде без доступа в интернет, поэтому не смог
  проверить их загрузку вживую. При деплое проверьте в консоли браузера,
  что они грузятся; при необходимости разместите локально в `static/`.
- Цветовая палитра взята из логотипа (оранжевый `#F09538`).
- `prefers-reduced-motion` учтён — анимация отключается для пользователей
  с соответствующей настройкой ОС.
- Таблицы в админке скроллятся по горизонтали на мобильных экранах.
